## 两项独立修改

### 条件转换与执行

复用现有Planner模型调用解释自然语言，加入由工具注册表提供的实际能力说明和共用条件schema。默认不增加每次工具前的模型转换。

- 明确时间、地点、人物、媒体、来源、数量单位和事件关系；记录所属需求、原文与证据来源。
- 时间区分拍摄／事件／文档时间；地点区分拍摄地、正文提及地、出发地、目的地和附近关系。
- 人物区分出镜者、拍摄者、作者、叙述者及动物。姓名／昵称／“我妈妈”等通过有效自我锚点和已有关系解析；实施前只读核验captured_by实际存储与覆盖。
- 后端生成同一份可执行条件，供搜索和统计共同使用，负责日期运算、实体定位和SQL生成。停止在不同工具里重新猜时间字符串，修正地点依赖人脸组的接线。
- 返回实际应用、未解析及不支持的条件。精确统计缺必要条件时明确失败，不能返回全相册统计并标成功；允许明确标记的探索搜索。
- Agent引用需求和已确认条件，依据工具证据补齐“最近旅行”“第三天”等事件锚点，再执行下游查询。不能用第一张照片替代行程起点，不能把商品罐数改成照片数。
- 身份有数据时保留检索能力；无数据、未命中、歧义和故障分别处理。没有新信息时复用解析状态，有新增昵称／关系证据时允许继续；必要身份条件不静默删除，匿名人脸能力仍保留。

这是一条完整链路，不将只改Planner提示词作为完成标准。

### 历史整理

作为独立开关，验证条件修复之外的长上下文问题，不混入条件组。

- 按输入预算组织历史；按稳定证据标识复用已读内容，减少重复检索结果和全文在上下文中的重复携带。
- 保留原问题、当前需求、关键事实、时间边界、未解条件和来源引用；新图、新字段及必要原文仍可读取。
- 完整原包／历史单独保存，不以删证据换成本；不新增模型摘要调用。
- 现有64组分页在各组保持一致，本轮不继续改分页。FinalGuard局部缺口误拦单列诊断，不同时改整体判定规则。

## 执行顺序

1. 用户确认后，先完成本机源码和现有数据覆盖核验，确定条件字段、工具接线及身份能力边界。
2. 本机实施两项独立机制，验证共用schema、跨工具过滤一致性、SQL结果、身份关系解析和历史证据保留。增加独立PhotoBench身份样例；不用ATM缺身份题决定关闭功能。
3. 先提交本机已验证代码，再同步独立候选目录，核SHA、编译、真实配置、记忆数据及旧答卷保持，验收后push。
4. 三个新组先各跑固定16题，检查实际条件、证据、成本和误拦。通过后同run继续余67题至83后暂停，首16不重做。发现条件丢失或误删必要身份等回归，先定位修复，不直接扩大。
5. 每题固定qa_id／trace_storage.revision取证，核全部content／trace分页read_revision；精确匹配HTTP原包与去重内部视觉，保留失败原因。
6. 按同题比较成本、查询语义和答案证据。Judge额度恢复后按同协议补正式分；尚未评分不记0。候选全1013和小预算复测不属于本轮自动扩展范围。

## 验收指标

- 条件：提取遗漏、错误收窄／放宽、实际执行与未执行原因；必要条件不能静默丢失。
- 身份：有数据能按昵称／关系找到正确实体，缺数据不循环，必要条件和角色不串用。
- 取证：事件锚点及最终结论有实际证据，真实无命中与数据覆盖不足分开。
- 开销：实际共享HTTP含Planner／核查／视觉／重试，工具准入、含去重视觉Token、本地超长预检次数及涉及题数分别统计。
- 质量：完成／带缺口／超时／模型错误按原因报告；正式分和新增漏答按冻结Judge核验，不能用答案相似或HTTP200代替。
- 时延：记录排队与单题耗时，保留共享网关条件，不将不同队列的一次运行差异直接解释为速度收益。

当前等待用户确认此范围；已有实验与三个有效只读监控保持。
